# StudioGate на Beget — инструкция для неразработчика

Ниже всё расписано как для человека, который **не пишет код**: куда зайти мышкой, что скопировать, что должно появиться на экране.

Если что-то пошло не так — остановитесь на этом шаге и напишите, на каком номере застряли и какой текст ошибки увидели.

---

## Сначала простыми словами: что мы делаем

У вас уже есть **VPS** (виртуальный сервер у Beget) — это компьютер в интернете, который всегда включён. На нём уже крутятся мелкие проекты.

Мы добавим туда ещё один проект — **StudioGate**:
1. Дадим ему адрес вида `https://gate.ваш-сайт.ru`
2. Запустим программу StudioGate на сервере
3. Свяжем адрес сайта с этой программой
4. Включим замочек HTTPS (безопасное соединение)
5. Потом пересоберём приложение для дизайнеров, чтобы оно само знало этот адрес

Ваши старые проекты **не удаляем и не переезжаем**.

## Часть A. Панель Beget — узнать IP и сделать адрес сайта

### Шаг A1. Зайти в Beget

1. Откройте браузер.
2. Перейдите на [https://cp.beget.com](https://cp.beget.com) (или обычный вход в кабинет Beget).
3. Войдите логином и паролем от Beget.

### Шаг A2. Найти IP вашего VPS

1. В меню слева найдите раздел вроде **«Облако»** / **«VPS»** / **«Виртуальные серверы»**.
2. Откройте ваш сервер (тот, где уже крутятся мелкие проекты).
3. Найдите блок **«Реквизиты доступа»**.
4. Там будет строка вида: `root@185.12.34.56`
5. **Число после `@` — это IP.** Запишите его.
6. Можно кликнуть по строке — часто она копируется целиком.

Пароль root обычно приходил **на почту** при создании VPS. Если забыли — в карточке сервера есть сброс/смена пароля.

### Шаг A3. Сделать поддомен `gate`

Нужен адрес вида `gate.ваш-домен.ru`.

**Вариант 1 — домен тоже на Beget (самый простой)**

1. В меню слева откройте **«Домены и поддомены»**.
2. Найдите ваш основной домен (например `studio.ru`) → нажмите на него или на «управление».
3. Нажмите **«Добавить поддомен»** (или похожую кнопку).
4. В поле имени поддомена напишите: `gate`  
   (получится `gate.studio.ru`)
5. Если спросят, куда направить:
   - выберите **«Направить на VPS»** и ваш сервер  
   **или**
   - «Не прилинковывать», а IP пропишем вручную в DNS (шаг A4).
6. Сохраните.

**Вариант 2 — домен куплен не у Beget**

Тогда DNS правите там, где куплен домен (REG.RU, Timeweb, Cloudflare и т.д.) — см. шаг A4.

### Шаг A4. Прописать DNS (A-запись)

Нужно сказать интернету: «адрес `gate.…` живёт на IP моего VPS».

**Если DNS у Beget:**

1. Меню слева → **«DNS»** или у домена кнопка **«DNS-записи»** / **«Редактировать DNS»**.
2. Выберите зону вашего домена.
3. **Добавить запись**:
   - Тип: **A**
   - Имя / хост / подзона: `gate`  
     (иногда пишут полное `gate.studio.ru` — смотрите, как у вас в других записях)
   - Значение / IP: **IP вашего VPS** из шага A2
4. Нажмите **«Добавить»** / **«Сохранить»**.

Подождите **от 5 минут до 2 часов** (иногда дольше). Это нормально.

### Шаг A5. Проверить, что адрес «дошёл»

На своём Windows-компьютере:

1. Нажмите клавишу **Win**, напишите `PowerShell`, откройте **Windows PowerShell**.
2. Вставьте команду (подставьте свой поддомен) и нажмите Enter:

```powershell
ping gate.ваш-домен.ru
```

**Хорошо:** видите ваш IP VPS в ответах.  
**Плохо:** «не удаётся найти хост» — DNS ещё не доехал, подождите и повторите. Дальше пока не идите.

## Часть B. Подключиться к серверу «чёрным окном» (SSH)

SSH — это просто способ управлять сервером текстом. Страшного в этом нет: вы будете **копировать готовые команды** и жать Enter.

### Шаг B1. Открыть окно на вашем компьютере

**Windows 10/11:**
1. Win → `PowerShell` → открыть.
2. Или Win → `cmd` → Командная строка.

**Mac:**
1. Программы → Утилиты → **Терминал**.

### Шаг B2. Подключиться

Вставьте (подставьте свой IP) и Enter:

```bash
ssh root@185.12.34.56
```

Первый раз спросят примерно:  
`Are you sure you want to continue connecting (yes/no)?`  

Напишите: `yes` → Enter.

Потом спросит пароль.  
**Важно:** при вводе пароля **ничего не видно** — ни звёздочек, ни точек. Это нормально. Введите пароль root и нажмите Enter.

**Получилось**, если слева появилось что-то вроде:
```text
root@vpsxxxxx:~#
```
или
```text
root@ubuntu:~#
```

Вы теперь «внутри» сервера. Все следующие команды — **в этом окне**, пока не напишете `exit`.

Если пишет `Permission denied` — неверный пароль.  
Если `Connection refused` / долго висит — на Beget проверьте, что VPS **включён**.

## Часть C. Поставить Docker (коробку для программ)

Docker — программа, которая запускает StudioGate в отдельной «коробке», не ломая ваши другие проекты.

### Шаг C1. Проверить, есть ли Docker уже

Скопируйте и Enter:

```bash
docker --version
```

**Если увидели** что-то вроде `Docker version 24...` — Docker уже есть, **переходите к части D**.

**Если написали** `command not found` / «команда не найдена» — ставим:

```bash
curl -fsSL https://get.docker.com | sh
```

Подождите 1–3 минуты. Потом:

```bash
docker --version
```

Должна появиться версия. Затем:

```bash
docker compose version
```

Если compose не найден:

```bash
apt-get update && apt-get install -y docker-compose-plugin
```

## Часть E. Секретный файл настроек (.env)

### Шаг E1. Придумать два длинных пароля

На сервере выполните **два раза** (каждый раз скопируйте результат в блокнот):

```bash
openssl rand -hex 32
```

Получите две длинные строки — это `JWT_SECRET` и `SESSION_SECRET`.

### Шаг E2. Создать файл `.env`

```bash
nano .env
```

Откроется простой текстовый редактор.  
Вставьте шаблон ниже и **замените** три вещи:
- `gate.ваш-домен.ru` → ваш поддомен
- две строки секретов → из шага E1

```env
DATABASE_URL=file:/data/studiogate.db
JWT_SECRET=сюда_первая_длинная_строка
SESSION_SECRET=сюда_вторая_длинная_строка
APP_URL=https://gate.ваш-домен.ru
NEXT_PUBLIC_APP_URL=https://gate.ваш-домен.ru
```

**Как сохранить в nano:**
1. Клавиши **Ctrl + O** (сохранить)
2. Enter (подтвердить имя файла)
3. **Ctrl + X** (выйти)

Проверка:

```bash
cat .env
```

Должны увидеть свои строки. В `APP_URL` обязательно `https://` и ваш реальный поддомен.

## Часть F. Запустить StudioGate

### Шаг F1. Сборка и старт

Стоя в папке `studio-access` (проверьте: `pwd` — путь должен заканчиваться на `studio-access`):

```bash
docker compose up -d --build
```

Первый раз может занять **5–15 минут**. Дождитесь возврата приглашения `#` без красных ошибок в конце.

Смотреть лог:

```bash
docker compose logs --tail=50
```

Выйти из лога, если «поехал» бесконечно: **Ctrl + C** (это только выход из просмотра, контейнер не убьёт).

### Шаг F2. Проверить, что внутри сервера сайт отвечает

```bash
curl -I http://127.0.0.1:3001
```

**Хорошо:** первая строка содержит `HTTP` и код `200` или `307` / `308`.  
**Плохо:** `Connection refused` — контейнер не запустился:

```bash
docker compose ps
docker compose logs --tail=100
```

Скиньте этот вывод — разберём.

### Шаг F3. Если порт 3001 уже занят другим проектом

```bash
ss -tlnp | grep 3001
```

Если что-то уже слушает 3001 — откройте файл:

```bash
nano docker-compose.yml
```

Найдите строку:
```yaml
- "127.0.0.1:3001:3001"
```
Замените на:
```yaml
- "127.0.0.1:3011:3001"
```
Сохраните (Ctrl+O, Enter, Ctrl+X) и снова:

```bash
docker compose up -d
```

Дальше в Nginx (часть G) пишите порт **3011**, не 3001.

## Часть G. Nginx — «указатель» с адреса сайта на StudioGate

Nginx у вас, скорее всего, уже стоит (раз крутятся другие сайты). Он принимает запросы с интернета и раздаёт их нужным программам.

### Шаг G1. Проверить, что Nginx есть

```bash
nginx -v
```

Если есть версия — отлично.  
Если нет:

```bash
apt-get update && apt-get install -y nginx
systemctl enable nginx
systemctl start nginx
```

### Шаг G2. Создать конфиг для StudioGate

```bash
nano /etc/nginx/sites-available/studiogate.conf
```

Вставьте целиком (замените `gate.ваш-домен.ru` и порт, если меняли на 3011):

```nginx
server {
    listen 80;
    server_name gate.ваш-домен.ru;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

Сохранить: Ctrl+O → Enter → Ctrl+X.

### Шаг G3. Включить сайт

```bash
ln -sf /etc/nginx/sites-available/studiogate.conf /etc/nginx/sites-enabled/studiogate.conf
nginx -t
```

**Хорошо:** `syntax is ok` и `test is successful`.  
Потом:

```bash
systemctl reload nginx
```

### Шаг G4. Проверка из браузера (пока без замочка)

Откройте на своём компьютере:

`http://gate.ваш-домен.ru`

Должен открыться лендинг **StudioGate** на русском («Доступ к Figma без хаоса с паролями»).

Если не открылось:
- DNS ещё не доехал (шаг A5)
- опечатка в `server_name`
- firewall Beget — в панели VPS откройте порты **80** и **443**, если есть файрвол

## Часть H. HTTPS — замочек в браузере (обязательно)

Без HTTPS вход в кабинет будет ломаться (куки/безопасность).

### Шаг H1. Установить Certbot (бесплатный сертификат)

```bash
apt-get update && apt-get install -y certbot python3-certbot-nginx
```

### Шаг H2. Выпустить сертификат

```bash
certbot --nginx -d gate.ваш-домен.ru
```

Ответьте на вопросы:
1. **Email** — ваш рабочий (для напоминаний о продлении)
2. Согласие с условиями — **Y** / Agree
3. Рассылка — можно **N**
4. Если спросит про редирект на HTTPS — выберите **Redirect** (обычно пункт 2)

**Хорошо:** в конце написано, что сертификат получен.  
Откройте в браузере уже с **https://**:

`https://gate.ваш-домен.ru`

Должен быть замочек и тот же лендинг.

## Часть J. Приложение для дизайнеров (чтобы не вводили ссылку руками)

Это делается **на вашем компьютере**, не на сервере.  
Нужен установленный Node.js (если нет — скачайте LTS с [https://nodejs.org](https://nodejs.org), установите «Next», перезапустите PowerShell).

### Шаг J1. Скачать код к себе на компьютер

Если пользуетесь GitHub Desktop / git — клонируйте репозиторий.  
Или скачайте ZIP репозитория → распакуйте → папка `studio-access`.

### Шаг J2. Прописать ваш сервер в приложение

Откройте файл блокнотом:

`studio-access/desktop/config.json`

Замените содержимое на (свой домен!):

```json
{
  "serverUrl": "https://gate.ваш-домен.ru",
  "productName": "StudioGate",
  "allowServerOverride": false
}
```

Сохраните файл.

### Шаг J3. Собрать установщик Windows

В PowerShell:

```powershell
cd путь\к\studio-access
npm install
npm run dist:win
```

Готовый файл появится в папке `studio-access/release/`.  
Его и отправляете дизайнерам (или выкладываете в GitHub Releases).

**Mac:** сборку `.dmg` нужно делать на Mac: `npm run dist:mac`.

Дизайнер: установил → открыл → вошёл вашей почтой/паролем → **Открыть Figma**.

## Частые ошибки простыми словами

| Что видите | Что это значит | Что делать |
|------------|----------------|------------|
| Сайт не открывается | DNS ещё не доехал или опечатка в имени | `ping gate.…`, подождать, проверить A-запись |
| 502 Bad Gateway | Nginx жив, а StudioGate внутри не отвечает | `docker compose ps` и `docker compose logs --tail=100` |
| Connection refused при curl | Контейнер не запущен | снова `docker compose up -d --build` |
| Permission denied по SSH | Неверный пароль root | сбросить пароль в панели Beget |
| Логин в кабинете «выбрасывает» | Нет HTTPS или в `.env` остался localhost | проверьте `https://` в `.env` и certbot |
| Порт уже занят | Другой проект на 3001 | сменить на 3011 в compose и Nginx |

# Какой сервер нужен для StudioGate

Коротко: **да, нужен постоянно работающий сервер**.  
Это не ваш Figma. Это **сервер StudioGate** (кабинет + доступы + сессии).

---

## Из чего состоит система

1. **Приложение StudioGate** на компьютерах дизайнеров  
   (скачали с GitHub Releases)

2. **Сервер StudioGate** где-то в интернете  
   (Next.js: логины, invite, revoke, хранение session Figma)

3. **Figma / Higgsfield**  
   (как обычно в облаке)

Приложение дизайнера всегда ходит на ваш сервер StudioGate.  
Если сервер выключен — Open не работает.

---

## Вариант A — ваш компьютер (только для короткого теста)

```bash
cd studio-access
npm run dev
```

Плюсы: быстро начать.  
Минусы:
- ноутбук должен быть включён;
- все в одной сети или нужен tunnel;
- неудобно для постоянной работы команды.

Подходит на 1–2 дня пилота, не для “всегда”.

---

## Вариант B — VPS / облако (правильно для команды)

Арендуете простой сервер и держите StudioGate там 24/7.

Подойдёт:
- Timeweb / Selectel / Aeza (РФ)
- Hetzner / DigitalOcean / Railway / Render / Fly.io

Минимум:
- 1 vCPU
- 1–2 GB RAM
- Ubuntu
- домен или IP

Тогда дизайнеры в приложении вставляют, например:
`https://gate.yourstudio.com`

И вам не нужно держать свой Mac включённым.

---

## Что именно деплоить на VPS

Папка `studio-access`:
- `npm run build`
- `npm run start` (порт 3001)
- база SQLite на диске (для пилота) или Postgres позже
- HTTPS (Caddy/Nginx)

Есть `Dockerfile` для простого запуска.

| Цель | Что делать |

---

## Ответ на ваш вопрос напрямую

> “Сервер должен быть постоянно включён — это мой компьютер?”

**Для постоянного использования — нет, лучше не компьютер.**  
Нужен небольшой VPS/облачный хостинг, где крутится StudioGate.

Ваш компьютер нужен только чтобы:
1. скачать/собрать приложение,
2. один раз Connect team Figma,
3. управлять людьми в кабинете с любого браузера.
